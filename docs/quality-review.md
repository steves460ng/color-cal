# 계산·동작 검증 보고서

검증일: 2026-10-23 (한국 시간)

검증 대상은 예외 발생 여부뿐 아니라 실제 제작값, 원본 측정값, 보정 버전, 계산기 출력 및 저장된 데이터의 일치 여부입니다. 실제 사용자 데이터 대신 분리된 테스트 프로젝트와 가상 Lab값을 사용했습니다.

## 확인하고 수정한 문제

| 항목                    | 기존 동작                                                                                        | 수정 후                                                                                                    |
| ----------------------- | ------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------- |
| 소수 반올림             | `1.005`를 소수점 두 자리로 제작할 때 `1.00`, `2.675`를 `2.67`로 처리할 수 있었음                 | 새 버전은 각각 `1.01`, `2.68`로 처리. 과거 제작값과 반올림 방식은 별도로 보존                              |
| 동일 측정값의 재입력    | `60`을 `60.000`으로 입력하거나 Lab 키 순서가 바뀌면 다른 원본으로 판단                           | 숫자와 명시된 필드로 비교하여 불필요한 버전 생성을 방지                                                    |
| 출력 조건 변경          | 용지·장비·잉크 등을 바꿔도 이전 테이블을 계산기에 적용할 수 있었음                               | 새 버전은 출력·측색 조건 사본을 보존하며, 현재 조건과 불일치하면 적용 차단                                 |
| 제작 가이드의 수치      | 소수 증분 2.5%, 표시 정밀도 0자리에서 가이드가 3으로 보이지만 측정 기준은 2.5로 계산될 수 있었음 | 1차 목표 입력을 화면·복사에서 정확히 표시. 파생 보정 제작값에만 지정된 반올림 적용                         |
| 2차 실제값 표시         | 실제 기록값 55.5555가 55.56으로 보일 수 있었음                                                   | 실제 기록값의 자릿수를 보존하여 표시                                                                       |
| 다른 입력값의 검증      | 테이블 제작값 50 대신 55로 측정해도 원래 테이블을 확정할 수 있었음                               | 비교·기록은 보존하되 테이블 제작값과 실제값이 다르면 확정 및 계산기 적용 차단                              |
| 백업의 계산 무결성      | 수치 범위·단조성을 만족하는 다른 테이블이 원본과 무관해도 복원을 통과할 수 있었음                | 원본으로 곡선을 재계산해 내부값과 대조. 값은 그대로 두고 일치하지 않는 백업을 거부                         |
| 과도한 수치의 중간 계산 | 입력 자체가 유한해도 색차·정규화 결과가 무한대가 될 수 있었음                                    | 보정 생성 및 결과 확정 전 중간값의 유한성 검사                                                             |
| 저장 상태 복구          | 한 번 실패하면 이후 정상 저장에도 실패 상태가 남을 수 있었음                                     | 프로젝트별 실패 상태 관리. 해당 프로젝트의 정상 저장 후 상태 복구                                          |
| 여러 탭의 덮어쓰기      | 오래된 탭의 전체 스냅샷이 최신 측정값을 덮어쓸 수 있었음                                         | IndexedDB 트랜잭션 안에서 저장 리비전을 비교해 충돌 시 쓰기·삭제를 중단하고 현재 초안은 백업 가능하게 유지 |

추가로 유효하지 않은 Lab 또는 실제 제작값을 그래프에 정상 데이터처럼 표시하지 않도록 조건을 맞췄습니다. 계산기에서도 활성 조건이 충족되지 않으면 채널 상태를 보정 대기로 표시합니다.

## 리팩터링

- `js/domain/values.js`: 수치·설정·Lab 검증, 패치 계조, 제작값 반올림
- `js/domain/calibration.js`: 단조 회귀, 보간·역보간, 보정 테이블 유도 및 검증, 버전별 반올림
- `js/domain/project.js`: 출력 조건 사본, 의미상 동일한 원본 비교, 이전 서명 형식 검증
- `js/storage/save-queue.js`: 저장 순서, 스냅샷, 프로젝트별 실패 상태와 리비전 전달
- `js/storage/indexeddb.js`: 원자적 리비전 검사 및 저장·삭제
- `js/ui/formatters.js`: 실제 입력값과 파생 제작값의 표시 분리

`js/core.js`의 기존 공개 함수는 유지하여 화면·테스트의 호출 경로를 보존했습니다. 알고리즘의 목표인 종이색 대비 ΔE76 계조 정규화와 PAVA 역선형 보간은 유지합니다.

## 호환성과 한계

기존 원본·버전·실제 제작값을 자동 재작성하지 않습니다. 과거 버전은 당시 반올림으로 제작·측정한 결과이므로 기존 제작값과 규칙을 유지합니다. 수정된 반올림을 사용하려면 새 버전을 생성해 제작·측정합니다.

조건 사본이 없던 과거 버전의 실제 장비·용지는 소급해서 알아낼 수 없습니다. 이후 출력 조건 편집은 감지하며, 새 버전부터 조건 사본을 저장합니다. 이전 데이터에 없는 조건까지 확인했다고 간주하지 않습니다.

확정은 자동 품질 합격 판정이 아닙니다. 실제값·테이블·버전의 일치 조건을 만족해도 출력 오차가 크면 작업자가 결과를 검토해야 합니다. 합성 데이터의 오차 감소율은 실제 장비의 성능 보증이 아닙니다.

브라우저 검증은 로컬 정적 서버의 Chromium 기준입니다. 공개 GitHub Pages 배포 상태, Firefox·Edge 및 실제 인쇄·측색계 작업은 이번 검증에 포함하지 않았습니다.

## 재현 명령

```sh
npm test
# 별도 터미널에서 저장소 루트의 정적 서버 실행
python3 -m http.server 8000
# 설치한 Playwright Chromium 사용
npm run test:browser
npm run test:behavior
npm run test:resilience
npm run test:persistence
```

시스템 Chromium 사용 시 `BROWSER_EXECUTABLE=/usr/bin/chromium`을 지정합니다. 서버 주소가 다르면 `BASE_URL`을 지정합니다. Node.js 24의 테스트 격리 비활성 옵션을 사용하여 모든 테스트 사례가 실행·집계되도록 구성했습니다.
